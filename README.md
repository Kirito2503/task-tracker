# Task Flow Tracker

Веб-сервис для управления проектами и задачами с аутентификацией, ролями и расчетом срочности.

## 1. Техническое задание

### Назначение
Сервис позволяет пользователям создавать проекты и задачи, назначать приоритеты, менять статусы и видеть вычисленную срочность задачи.

### Роли
- `USER` видит только назначенные ему задачи и собственные проекты.
- `ADMIN` видит все проекты и задачи, может назначать задачи пользователям и удалять задачи.
- Самостоятельная регистрация всегда создает только `USER`. Администратор создается отдельно с доступом к БД или миграцией.

### Функциональные требования
- регистрация и вход по email/паролю;
- JWT-аутентификация;
- CRUD проектов и задач;
- фильтрация задач по приоритету и статусу;
- журналирование изменения статусов;
- расчет срочности: `DONE -> CLOSED`, `HIGH -> CRITICAL`, `MEDIUM -> WARNING`, `LOW -> REGULAR`;
- разграничение доступа по роли и владельцу/назначенному пользователю;
- веб-интерфейс для входа, создания и фильтрации задач.

### Ограничения данных
- приоритет: `LOW`, `MEDIUM`, `HIGH`;
- статус: `TODO`, `IN_PROGRESS`, `DONE`;
- проект обязателен для задачи;
- email пользователя уникален.

## 2. Структура базы данных

База MySQL содержит четыре таблицы: `users`, `projects`, `tasks`, `task_logs`. SQL-схема находится в [init.sql](init.sql), ER-диаграмма: [docs/er-diagram.md](docs/er-diagram.md).


## 3. Запуск локально

```powershell
npm install
docker-compose up -d db
npm start
```

Локальное приложение: `http://localhost:8080`.

Для запуска всего стека в Docker:

```powershell
docker-compose up --build
```

В этом режиме приложение доступно на `http://localhost:3000`, а MySQL с хоста на `localhost:3307`.

Настройки запуска Node с хоста находятся в `.env`. Файл `.env` не добавляется в Git; пример переменных:

```text
PORT=8080
DB_HOST=localhost
DB_PORT=3307
DB_USER=root
DB_PASSWORD=root_password
DB_NAME=tasktracker
JWT_SECRET=change_me
```
